# What the agent established

- (active) A k=16 Adam-trained Factorization Machine using user_id, video_id, author_id, tab, and duration_bucket reproduces the official baseline within seed noise (primary 0.6026 versus 0.6016) but provides no measurable improvement. [iters 1]
- (active) Replacing the five-field Factorization Machine with the tested DeepFM and validation-selected blending does not measurably improve within-user ranking over the reproduced FM baseline (primary 0.6039 versus 0.6026, a difference of 0.0013). [iters 1,2]
- (active) For the tested DeepFM, blending with the trusted FM at weight 0.75 changes primary by only 0.0001 relative to the raw candidate (0.6039 versus 0.6038), so this blending step has no measurable effect. [iters 2]
- (active) Adding the tested hierarchical empirical-Bayes user-content affinities and robust entity-rate residual corrections to the DeepFM incumbent does not measurably improve within-user ranking (primary 0.6043 versus 0.6039, a difference of 0.0004). [iters 2,3]
- (active) The correction-selection procedure retained only user-pair corrections for hour, tag, and author, with weights 0.2, 0.1, and 0.05 respectively; entity-rate residuals and pair corrections for duration, upload context, and video were not retained in the final scored correction set. [iters 3]
- (active) Adding the tested leakage-free, target-conditioned user-history features for video, author, tag, tab, hour, and related context does not measurably improve over the personalized-correction incumbent (primary 0.6045 versus 0.6043, a difference of 0.0002). [iters 3,4]
- (qualified) The history-feature LightGBM relied strongly on constructed temporal features such as tab_history_residual, user_history_residual, tab_history_count, video_history_residual, and hour_history_residual, but their inclusion produced no measurable ranking gain; gain importance alone is therefore not evidence that this feature family helps. [iters 4]
- (active) Adding the tested transductive, label-free candidate-set features—within-user entity-rate percentiles, centered deviations, z-scores, candidate-set size, and repeated-exposure frequencies—does not measurably improve over the history-feature incumbent (primary 0.6045 versus 0.6045). [iters 4,5]
- (qualified) The candidate-set model assigned high gain importance to features including tab_entity_rate_residual, tab_entity_log_count, and tab_entity_rate_user_set_percentile, but the full candidate-set feature package produced no measurable primary gain, so these importance values do not establish ranking benefit. [iters 5]
- (qualified) The tested standalone setwise auxiliary was substantially worse than the incumbent on this validation split (raw_setwise_primary 0.4581), and validation selected only a 0.05 setwise blend weight; this argues against using that specific setwise formulation as the primary ranker. [iters 5]
- (active) For both the history-feature and candidate-set candidates, external harness blending selected alpha 1.0, so their scored primary values equal their raw candidate values and external incumbent blending added no measured benefit. [iters 4,5]
- (qualified) Across the tested baseline, DeepFM, personalized-correction, target-conditioned-history, and candidate-set evaluations, recall@50 is saturated at 1.0000 and is unlikely to distinguish nearby model variants without changing the candidate or evaluation setup. [iters 1,2,3,4,5]
- (active) Four consecutive modifications—DeepFM, personalized corrections, target-conditioned history, and transductive candidate-set features—failed to improve the preceding incumbent by more than the 0.002 noise threshold, so the run's stopping criterion has been met. [iters 1,2,3,4,5]
